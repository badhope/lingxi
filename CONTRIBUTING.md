# Contributing to DATA-Agent

Thank you for your interest in contributing to DATA-Agent! 

## 🎯 Ways to Contribute

There are many ways you can contribute to DATA-Agent:

- 🐛 **Bug Reports**: Report bugs or issues
- 💡 **Feature Requests**: Suggest new features
- 📖 **Documentation**: Improve or translate documentation
- 🔧 **Code Contributions**: Submit pull requests
- 🧪 **Testing**: Help test the project
- 📢 **Community**: Help other users

## 🚀 Getting Started

### Prerequisites

- Python 3.10 or higher
- Git
- OpenAI API key (for testing)

### Development Setup

1. **Fork the repository**
   ```bash
   git clone https://github.com/your-username/DATA-Agent.git
   cd DATA-Agent
   ```

2. **Create a virtual environment**
   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install dependencies**
   ```bash
   cd dataagent
   pip install -r requirements.txt
   ```

4. **Create a feature branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

## 📝 Making Changes

1. **Code Style**
   - Follow PEP 8 guidelines
   - Use meaningful variable and function names
   - Add docstrings to functions and classes
   - Keep functions focused and small

2. **Commit Messages**
   - Use clear, descriptive commit messages
   - Start with a verb (Add, Fix, Update, Remove)
   - Reference issues when applicable

   Example:
   ```
   Add new researcher agent for market analysis
   
   Implemented a new researcher agent that specializes in market
   data collection and analysis. This agent works with the
   existing analyst and writer agents.
   
   Fixes #123
   ```

3. **Testing**
   - Write tests for new features
   - Ensure all tests pass before submitting
   - Include both positive and negative test cases

## 🔄 Pull Request Process

1. **Update Documentation**
   - Update the README.md if needed
   - Add docstrings to new functions
   - Include usage examples for new features

2. **Submit Pull Request**
   - Fill out the PR template completely
   - Link to related issues
   - Describe your changes in detail

3. **Review Process**
   - Be responsive to feedback
   - Make requested changes promptly
   - Keep the PR focused and small

## 🐛 Bug Reports

When filing a bug report, please include:

- **Description**: Clear description of the bug
- **Steps to Reproduce**: How to reproduce the bug
- **Expected Behavior**: What you expected to happen
- **Actual Behavior**: What actually happened
- **Environment**: OS, Python version, etc.
- **Logs**: Any relevant error messages or logs

## 💡 Feature Requests

For feature requests, please include:

- **Use Case**: How would you use this feature?
- **Proposed Solution**: How do you think it should work?
- **Alternatives**: Any other solutions you've considered?

## 📖 Documentation

Good documentation is essential! Please:

- Use clear, simple language
- Include code examples
- Add comments in code
- Keep documentation up-to-date
- Translate to multiple languages (especially English and Chinese)

## 🎨 Code of Conduct

Please read our [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) to understand what behavior is expected and what will not be tolerated.
